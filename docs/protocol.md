# Cube World protocol (reverse engineered)

Reverse engineered from the three protocol captures and the sigrok
decoder in [npjg/radica-cube-world-hack](https://github.com/npjg/radica-cube-world-hack),
then verified byte-for-byte against the raw 2 MHz logic-analyzer
samples in the `.sr` files. All timings below are measured ranges
across all three captures (559 packets).

## Physical layer

- One data line, **pull-up terminated** (idle = high).
- 3.3 V logic (the toys run at 3.3 V).
- Half-duplex, unidirectional per direction: a cube that wants to talk
  drives the line low for each pulse and floats it high between pulses.
- Two toys are wired together by joining their data lines.
- A packet is ~7.0-7.6 ms of wire activity; idle between packets is
  high.

## Frame structure

```
   L 234-240 | H 52-53 | L 92-101 |  28 x [ H gap | L bit ]  |  H 56-57 | L 92-94
   <----------- preamble ---------->                          <------- postamble ->
```

### The 28 bits

Each bit is a **high gap followed by a low pulse**:

| field | measured range | notes |
|---|---|---|
| gap before bit 0 | 136-142 us | special: not the usual inter-nibble gap |
| inter-nibble gap (bits 4,8,12,16,20) | 194-205 us | |
| intra-nibble gap (other bits) | 98-118 us | |
| gap before bit 24 | 106-107 us | quirk: nibble 7 starts with a short gap |
| low pulse = bit 0 | 94-113 us | |
| low pulse = bit 1 | 173-176 us | |

Decode boundary used by the codec: low <= 115 us -> 0, low >= 150 us ->
1 (both sides have >30 us of margin against the measured ranges).

Bits are MSB first: bit 0 is the top nibble bit of packet nibble 0.

## Packet payload: 7 nibbles

```
 [0] type | [1] p1 | [2] p2 | [3] p3 | [4] p4 | [5] sender id | [6] trailer
```

### Message types (nibble 0)

| type | name | observed shape | notes |
|---|---|---|---|
| `0x1` | HELLO | `1 f 1 5 1 id 9` | p1 is `0x7` or `0xf`; p4 is `1` or `2`. Session start, one per cube, in turn. |
| `0x2` | KEEPALIVE | `2 s 0 0 0 id 9` | `s` = slot (0..3), round-robin, ~every 350 ms. |
| `0x6` | ACTION (whip) | `6 a b c 0 id 9` | a in {1,2}, b in {0,2}, c in {2..0xf}. The sender whips; the target is the *other* cube(s). |
| `0x7` | BYE | `7 0 0 0 0 id 9` | near the end of a session. |
| `0x8` | END | `8 0 0 0 0 id 9` | last packet of a session. |
| `0x9` | unknown | `9 0 0 0 0 7 9` | seen 5x, always p5 = 7; purpose unexplained. |

**The trailer (nibble 6) is `0x9` in all 559 observed packets.** It is a
good cheap validity check.

## Session lifecycle

Observed across all three captures:

```
HELLO (cube A)   ~250 ms apart, each cube once
HELLO (cube B)
HELLO (cube C)
KEEPALIVE x N    round-robin by slot, ~350 ms period
ACTION (whip)    1-2 whips, 3.5-8 s apart
... (session lasts ~45-75 s)
BYE
END
```

Sender ids are assigned per session (they differ between captures), so
a receiver should re-identify cubes from the HELLO phase.

## The three example captures

| capture | duration | traffic |
|---|---|---|
| `1Whip_1Dodger` | 62.9 s | 187 packets: 3 HELLO, ~170 keepalives, **2 WHIP (both at Dodger, who dodges)**, 1 BYE, 1 END |
| `1Whip_2Handy` | 49.9 s | ~150 packets: HELLO x3, keepalives, **2 WHIP (both at Handy)**, BYE, END |
| `1Whip_2Hans` | 73.0 s | ~200 packets: HELLO x3, keepalives, **2 WHIP (both at Hans)**, BYE, END |

The decoded packet streams are checked into `tools/captures.json`
(generated by `tools/parse_captures.py`); the replay sketches consume
the same data.

## Decoder state machine

`CubeProtocol::readPacket()` (see `firmware/libraries/OpenCubeWorld/`):

1. Scan for the preamble: L in [200,300], H in [40,80], L in [60,130].
   (Any earlier low blip is ignored - this also absorbs the attention
   pulses used by `pollForPeer`.)
2. Read 28 bit slots; each slot needs a high gap > 80 us followed by a
   low pulse classified 0/1. A gap <= 80 us mid-packet means
   end-of-packet -> fail.
3. Consume the postamble: H (any, <= 200 us), L in [60,130].
4. Reassemble 7 nibbles, check the trailer.

The upstream sigrok decoder (`sigrok-decoder/cube-world/pd.py` in the
hack repo) implements the same rules for PulseView.

## Quirks & caveats

- The gap before bit 0 (~140 us) and the short gap before bit 24
  (~106 us) do not follow the 200/100 pattern; the transmit path
  reproduces both.
- Bit-0 low pulses drift up to ~113 us under load; keep the decode
  boundary at ~115-150 us.
- Cube ids are not stable across sessions; slots (in keepalives) are
  the stable address.
- Nothing in the captures shows a cube refusing a whip; dodging is
  rendered from the WHIP packet alone (target = the other cube).
- Type `0x9` is undocumented; treat as "unknown" and ignore.
